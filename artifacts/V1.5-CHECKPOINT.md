# V1.5 keyless implementation checkpoint

Updated 2026-10-23. The authorized keyless implementation and local verification are complete. Read artifacts/V1.5-KEYLESS-VERIFICATION.md for evidence and limits, and docs/channel-setup.md for setup and later activation checks.

## Scope and production state

The user requested WhatsApp, Facebook Messenger and Instagram integration built and tested WITHOUT production keys. No production credentials were retrieved or used, no remote database migrations or deployments were performed, no real messages were sent, and no user passwords were changed. Do not push main, which deploys automatically. V1.4 remains the previously verified production baseline at commit 462766ffe2d6e72628ab3a81bc43e4ed6d085dfa. Its heartbeat is paused; do not resume it for V1.5.

## Implemented

- Raw-body HMAC webhooks, account scoping, bounded payloads, atomic durable intake and deduplication for all three channels.
- Local supabase/v1.5.sql: scoped conversations, immutable activity entries, AI jobs, outbox, receipts, leases, RLS and staff/service RPC grants. Existing migration sequence and demo behavior retained.
- Staff conversation panel, authorized replies, AI draft approval, takeover, explicit new enquiries, Admin configuration readiness.
- Default disabled mode, private Meta secret references, explicit send gates and recipient allowlists, loopback-only nonproduction sandbox.
- Worker leases, stale-result checks, rate-limit retries, conservative unknown-outcome barriers, receipt reconciliation and bounded recovery. Staff/channel advisory locks share a consistent order.
- Server-only AI adapter; offline verification injects a deterministic generator and never calls OpenAI.

## Final verification

- npm test: 69 passed, 0 failed, 0 skipped. Includes actual application migrations in isolated PGlite PostgreSQL and signed inbound events through the real parser/worker/provider to a loopback HTTP mock for WA/FB/IG.
- npx tsc --noEmit: passed after typing-only cleanup in the new locking tests.
- npm run build: passed, including Next.js type checks and route generation.
- Compiled app HTTP smoke: public pages available, anonymous dashboard redirects, Admin API denies anonymous access, all three webhook routes and worker fail closed while disabled.
- Final independent source review: no blocking credential, authorization or activation issue found.

Windows sandbox prevents some loopback HTTP connections and Next build writes; the authorized local tests/build ran with the execution override. HTTP fixtures have an outbound origin guard and contain dummy credentials only. Do not weaken this guard to resolve sandbox failures. Package test flags bound Node24 WebAssembly compilation memory for pinned PGlite 0.5.11.

## What remains before real activation

Use a separate staging database, stable HTTPS staging deployment and Meta test assets/credentials. Verify actual Auth login, native concurrent PostgreSQL sessions, real callbacks/delivery, account permissions/review, templates, hosted worker scheduling and AI quality. PGlite plus mock HTTP cannot certify these external dependencies. Keep production keys and channels disabled until this stage passes. Media is metadata-only; review it in the provider inbox. Forms/comments/history import and cross-channel contact merging are outside the initial direct-chat scope.

No further keyless development is blocked on a production key. Later real-provider verification requires designated Meta test assets, not the production key.
